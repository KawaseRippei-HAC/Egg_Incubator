# 卵演出 統合ガイド ― 本番実装への組み込み

対象: タマゴインキュベーター(仮)
このドキュメントが対象とする既存資料: `EggCrackGlow_Guide.md`(ひび割れ発光) / `落下破壊表現_実装ガイド.md`(落下破壊) / `孵化演出_実装ガイド.md`(孵化)

## このドキュメントの目的

上記3つの実装ガイドは、それぞれの演出が「何をするか」を説明しています。
このドキュメントはその一段上のレイヤーとして、次の4つに絞って書かれています。

1. テストプロジェクトの成果物を**本番プロジェクトへどう持ち込むか**
2. 3Dモデル・アニメーション・シェーダーパラメータを**どう差し替えるか**
3. バランス管理・タイマーなど**他メンバーのコードとどう連携させるか**(イベント駆動)
4. 「画面を揺らす」のような**新しい演出をどう追加するか**

このドキュメントに書かれているスクリプトのフィールド名・メソッド名・既定値は、すべて実際の
`Assets/Scripts/EggBreakController.cs` / `EggHatchController.cs` / `EggCrackGlowController.cs` の
現物を読んで確認したものです。想像で書いた記述はありません。

# 1. 全体像

## 1.1 3つの演出の役割分担

| 演出 | スクリプト | 発火条件(想定) | 卵はどうなるか |
|---|---|---|---|
| ひび割れ発光 | `EggCrackGlowController` | 常時。危険度(`dangerLevel` 0〜1)に応じて殻が光る | 見た目が変わるだけで、メッシュの切り替えは起きない |
| 落下破壊 | `EggBreakController` | 卵が台から落下し、地面等に衝突した瞬間(失敗) | 殻(`shellWhole`)→8破片(`fracturedPieces`)に切り替わり、勢いよく弾ける |
| 孵化 | `EggHatchController` | 制限時間を耐えきった瞬間(成功) | 予兆(揺れ+発光)→殻→薄い8破片(`hatchFragments`)+キャラクターに切り替わり、穏やかに弾ける |

**この3つは同じ卵(`Egg_Test`)に同居していますが、「落下破壊」と「孵化」はゲーム上は排他的な結末です。**
両方のコンポーネントは今のテストシーンでは「どちらも未発火のまま同時に有効」になっているため、
**実際に排他制御を入れるのは呼び出し側(ゲームロジック)の責任**です。この設計自体は意図的なもので、
「テスト時にどちらも単体で試せるように」あえて疎結合にしてあります。実装方法は 4.6 章で扱います。

## 1.2 現在のヒエラルキー(3演出を合成した状態)

```
Egg_Test                         ← Rigidbody / EggCrackGlowController / EggBreakController / EggHatchController
 ├─ Egg_RadialGlow                ← ひび割れに連動する放射光条(EggCrackGlowControllerが自動検出)
 ├─ EggFragments                  ← 落下破壊用の8破片(立体的・重い・Kinematic待機)
 │   └─ Egg_Frag_01〜08
 └─ EggHatch                      ← 孵化用一式(初期状態は非表示)
     ├─ HatchFragments             ← 孵化用の8破片(薄い外殻のみ・Egg_Fragと境界は同じ・Kinematic待機)
     │   └─ HatchShell_01〜08
     └─ Character                  ← Animatorでキーフレームアニメーション再生(現状は仮モデル)
```

3つのコントローラーはすべて **`shellWhole`(割れていない卵メッシュ)を共通の入力として参照**しています。
`EggBreakController.shellWhole` と `EggHatchController.shellWhole` には同じオブジェクトを指定して構いません
(実装ガイドにもその旨明記されています)。

## 1.3 重要な依存関係:`testAutoPlay` に注意

`EggCrackGlowController` には `testAutoPlay`(既定値 **true**)というフィールドがあり、有効なままだと
`Update()` の中で毎フレーム `dangerLevel` を 0→1→0 に自動で往復させ続けます。

```csharp
// EggCrackGlowController.cs 抜粋
private void Update()
{
    if (testAutoPlay)
    {
        float t = Mathf.PingPong(Time.time / (testCycleSeconds * 0.5f), 1f);
        dangerLevel = t; // ← 外部から dangerLevel をセットしても毎フレーム上書きされる
    }
    ...
    SetDangerLevel(finalAmount);
}
```

**本番でタイマー等から危険度を制御する場合は、必ず `testAutoPlay = false` にしてください。**
そうしないと、他のスクリプトが `SetDangerLevel()` を呼んでも次のフレームで上書きされてしまいます。
なお `EggHatchController` は孵化演出の間だけ内部で自動的に `testAutoPlay` を退避・OFF・復元しているため、
孵化トリガー経由であればこの問題は起きません(4.3節で詳述)。

# 2. 本番プロジェクトへの持ち込み手順

## 2.1 前提:検証済みのこと / まだ検証されていないこと

各ガイドの「受け入れ基準との対応」「動作確認済みの内容」を踏まえると、次のように整理できます。

| 検証済み | 未検証・本番で要確認 |
|---|---|
| 座標のズレ(ワープ)が起きないこと | 実際の台(フライパン)の形状・Physic Materialでの挙動 |
| 破片が卵の速度・勢いを引き継ぐこと | 破片8個という分割数が実プレイに合っているか |
| 落下の勢い/穏やかさによる弾け方の差 | Android実機でのBloomの見え方(PC Editorと差が出る可能性あり、受け入れ基準に明記) |
| ランダムな回転・横倒し姿勢からの孵化 | 演出フック(パーティクル・SE・カメラシェイク)は**すべて未設定** |
| コライダー貫通問題の原因と対処(6章) | 落下破壊と孵化の排他制御(呼び出し側で未実装) |

## 2.2 持ち込むファイル一覧

| 種別 | パス | 備考 |
|---|---|---|
| シェーダー | `Assets/Shaders/EggCrackGlow.shader`, `EggRadialBurst3D.shader` | HLSL手書き。コピーのみでOK |

| モデル | `Assets/Models/Egg_Mesh.fbx`(卵本体+破片) / `Assets/Models/EggHatch.fbx`(孵化破片+キャラクター) / `Assets/Models/LightBurst_Mesh.fbx`(光条) | 本番の卵デザインに差し替える場合は3章を参照 |

## 2.3 本番の卵GameObject/Prefabへの組み込み手順

3つの実装ガイドの「実際のゲームへの取り込み方」を統合すると、次の順序になります。

### Step 1: Rigidbody(1個だけ)
本番の卵に **Rigidbody は1つだけ**、卵の一番親(トップレベル)に設定します。
`EggBreakController` と `EggHatchController` はどちらも `[RequireComponent(typeof(Rigidbody))]` なので、
Rigidbodyが無いとAddComponentできません。バランス崩壊などの既存の物理演算で使っているRigidbodyが
既にあるならそれを流用してください(検証シーンで追加したもの: 質量0.06・SphereCollider半径0.5は検証用の仮設定です)。

> ⚠️ **13章で判明した重要な注意点**: 子オブジェクト(`Egg_RadialGlow` など)に誤ってRigidbodyを
> 追加しないこと。親子で複数のRigidbodyが混在すると、台をすり抜ける・貫通するなどの物理挙動の
> 不具合が起きます。Rigidbodyは階層の最上位にのみ置いてください。

### Step 2: 殻本体(`shellWhole`)へのシェーダー適用
卵メッシュのマテリアルに `Custom/EggCrackGlow` を割り当てたマテリアルを設定し、`EggCrackGlowController`
をアタッチします(2.4節のチェックリストも参照)。

### Step 3: 破片群を子として配置
`EggFragments`(落下破壊用)と `EggHatch`(孵化用、内部に`HatchFragments`+`Character`)を、
**卵と同じローカル原点(0,0,0)・回転なし・スケール1** で子として配置します。
ここがズレると、表示切替の瞬間に破片が「ワープ」して見えます(落下破壊ガイド 3章・補足を参照)。

### Step 4: `EggBreakController` / `EggHatchController` の設定
`Egg_Test` 相当の本番オブジェクトに両方をアタッチし、Inspectorで参照を割り当てます。

| コンポーネント | 割り当てる参照 |
|---|---|
| `EggBreakController.shellWhole` | 殻メッシュ本体 |
| `EggBreakController.fracturedPieces` | `EggFragments` |
| `EggHatchController.shellWhole` | 殻メッシュ本体(上と同じでよい) |
| `EggHatchController.hatchVisual` | `EggHatch` |
| `EggHatchController.hatchFragments` / `character` / `hatchAnimator` | 未設定でも `hatchVisual` から自動取得を試みる(`Awake()`内の`transform.Find`) |
| `EggHatchController.crackGlowController` | 未設定でも `shellWhole.GetComponent<EggCrackGlowController>()` で自動取得される |

### Step 5: 発火方式を選ぶ
- `EggBreakController.autoTriggerOnCollision` を `true`(既定)のままにする場合は、台(フライパン)に
  `Ground` タグを付けるだけで衝突時に自動発火します。
- `false` にする場合は、バランス崩壊ロジック側から `eggBreakController.TriggerBreak();` を直接呼びます。
- `EggHatchController` には衝突トリガーの仕組みはなく、**必ず外部(タイマー等)から `TriggerHatch()` を
  呼ぶ設計**になっています(4章で詳述)。

## 2.4 組み込みチェックリスト

- [ ] Rigidbodyは卵の最上位に1つだけ(子オブジェクトに重複していないか)
- [ ] `shellWhole` / `fracturedPieces` / `hatchVisual` などの参照がInspectorで全て埋まっている
- [ ] 破片群(`EggFragments`, `EggHatch`)のローカル座標が卵と同一原点・回転なし・スケール1
- [ ] 破片の各メッシュに `MeshCollider(Convex ON)` + `Rigidbody(isKinematic ON)` が付いている
- [ ] `EggCrackGlowController.testAutoPlay` を、本番でタイマー駆動する場合は `false` にしてある
- [ ] 台(フライパン)側のColliderが `Ground` タグを持っている、または衝突ベースを使わない設計になっている
- [ ] `breakParticles` / `breakAudioSource` / `breakSfx` / `onBreak`、`hatchParticles` / `hatchAudioSource` /
      `hatchSfx` / `onHatch` のうち、本番で使うものを割り当てた(未設定でもエラーにはならず、単に無音・無エフェクトで動く)

# 3. 素材の差し替え方法

## 3.1 3Dモデル(卵メッシュ・破片)を差し替える場合

卵のデザインそのものを変える場合は、Blender側で新しい卵メッシュから改めて破片を作り直す必要があります。
落下破壊ガイドの「Voronoi的分割」の考え方(8破片・全て水密・PhyxXの凸包256面制限内)を踏襲してください。

**エクスポート時の必須設定**(孵化ガイド6章より、両方のFBXに共通):

| 設定項目 | 値 | 理由 |
|---|---|---|
| `Apply Scalings` | **FBX All** | これ以外だとUnity側でオブジェクトの見た目スケールとメッシュサイズがズレ、**100倍(または1/100)のサイズになる事故**が起きる |
| `Apply Unit` | ON | 単位系のズレを防ぐ |
| `Selected Objects Only` | ON | 空(Empty)の親(`Egg_FragmentsRoot`, `Egg_HatchRoot`)自体は選択せず、中身の破片・キャラクターのみ選択してエクスポート |
| `Forward` / `Up` | -Y / Z(既定のまま) | Unity側の向きと一致させる |

再インポート後、Projectウィンドウで対象FBXを右クリック→ `Reimport` を忘れずに行ってください。

**破片の数・名前を変えた場合**(モデルの分割数を変える等)は、既存のシーン上インスタンスは更新に追従しないため、
孵化ガイド6章の「シーン再構築手順」(プレハブ接続解除→`HatchFragments`作り直し→各破片へ
`MeshCollider(Convex)`+`Rigidbody`再設定→参照の貼り直し)が必要です。
**メッシュ形状だけの差し替え**(数・名前は変えない)であれば、この再構築は不要です。

## 3.2 キャラクターモデル・アニメーションを差し替える場合

孵化ガイド5章の手順に沿います。要点は次の3つです。

1. `Character` というオブジェクト名と、`Egg_HatchRoot` の子であるという階層構造は**維持したまま**メッシュだけ差し替える
2. 位置・回転・スケールのキーフレーム(フレーム1〜75、30fps、`Scene`クリップ)はオブジェクトに紐づいているため、
   メッシュ形状だけ差し替えれば動きはそのまま引き継がれる
3. サイズが大きく異なる素材に差し替える場合は、フレーム1(待機スケール0.12)を含む各キーフレームのスケール値を
   手動調整してバランスを取る(卵の内寸: 幅1.56×奥行1.56×高さ2.1 Blender単位が目安)

> ⚠️ **実機配置での注意(孵化ガイド5章より)**: テスト環境では卵がY=3.4付近に浮いた状態で置かれていますが、
> `Character`のアニメーションは卵からの**相対座標**でしか動きません。実際に卵が台に接地した状態で孵化させる
> 場合は、破片(物理演算で正しく台に落ちる)とキャラクター(卵基準の相対アニメーション)の着地高さが
> ズレないよう、実配置に合わせて`Character`のキーフレームのZ位置を調整してください。

## 3.3 シェーダーパラメータの調整(色・演出のトンマナ変更)

`Custom/EggCrackGlow` と `Custom/EggRadialBurst3D` はコードを触らずマテリアルのInspectorだけで見た目を
大きく変えられます。よく使う組み合わせを表にまとめます(詳細な全パラメータは `EggCrackGlow_Guide.md` 4章・
10章・12章を参照)。

| やりたいこと | 触るパラメータ |
|---|---|
| 亀裂を細かく/大きくしたい | `_CrackScale`(既定7、1〜20) |
| 亀裂がなめらかに/パキッと出現するようにしたい | `_GrowthSoftness`(小さいほどシャープ)、`_Jaggedness`/`_JagFrequency` |
| 発光色を変えたい(暖色=生命感、冷色=不穏) | `_EmissionColor` / `_EmissionIntensity`(Bloom Thresholdとセットで調整) |
| 光条の神秘的な質感を強めたい | `Egg_RadialBurst3D`の`_FresnelPower`/`_FresnelMin`、色は`_RayColor` |

## 3.4 危険度(`dangerLevel`)を差し込むタイミングの差し替え

現状はテスト用に `testAutoPlay` で自動往復させていますが、本番では次の1行を好きなタイミングで呼ぶだけで
危険度演出を差し込めます(**呼ぶ前に `testAutoPlay = false` を忘れずに**、1.3節参照)。

```csharp
eggCrackGlowController.SetDangerLevel(dangerLevel); // dangerLevel: 0〜1
```

# 4. 他メンバーのコードとの連携方法(イベント駆動)

## 4.1 全体の呼び出し関係

```
[バランス管理スクリプト]                 [タイマー/ゲームマネージャー]
   落下確定を検知                            制限時間の残りを監視
        │                                        │
        ▼                                        ▼
 eggBreakController.TriggerBreak()      eggHatchController.TriggerHatch()
        │                                        │
        ├─ 破片を物理的に弾く                       ├─ 予兆演出(揺れ+発光)
        ├─ breakParticles.Play()                  ├─ 破片を弾く
        ├─ breakAudioSource.PlayOneShot()          ├─ Character の Hatch アニメーション再生
        └─ onBreak.Invoke() ──▶ 拡張フック          └─ onHatch.Invoke() ──▶ 拡張フック

[タイマーの残り時間] ──毎フレーム/一定間隔で──▶ eggCrackGlowController.SetDangerLevel(t)
                                                  (testAutoPlay=false が前提)
```

**ポイント**: 落下破壊・孵化のどちらも、呼び出し側は「イベントが起きたこと」を通知する1行を呼ぶだけでよく、
演出内部の物理計算やアニメーション制御を呼び出し側が意識する必要はありません。

## 4.2 公開API早見表

### `EggBreakController`

| メンバー | 型 | 役割 |
|---|---|---|
| `TriggerBreak()` | メソッド | 破壊を開始する(多重発火防止つき) |
| `ResetForTesting()` | メソッド | 破壊状態をリセットする(実プレイでは通常呼ばない) |
| `shellWhole` / `fracturedPieces` | `GameObject` | 殻本体 / 破片群の参照 |
| `autoTriggerOnCollision` / `groundTag` | `bool` / `string` | 衝突ベース自動発火のON/OFFとタグ |
| `baseExplosionForce` 他5個の力・速度パラメータ | `float` | 5章のパラメータ表を参照 |
| `breakParticles` / `breakAudioSource` / `breakSfx` / `onBreak` | 演出フック | 未設定でも動作する(5章で使い方) |

### `EggHatchController`

| メンバー | 型 | 役割 |
|---|---|---|
| `TriggerHatch()` | メソッド | 孵化を開始する(多重発火防止つき) |
| `ResetForTesting()` | メソッド | 孵化状態をリセットする |
| `shellWhole` / `hatchVisual` / `hatchFragments` / `character` / `hatchAnimator` | `GameObject`等 | 各パーツの参照(未設定分は`Awake()`で自動取得を試みる) |
| `hatchTriggerName` | `string` | Animatorに送るTriggerパラメータ名(既定`"Hatch"`) |
| `anticipationDuration` / `shakeAngle` / `shakeFrequency` | `float` | 予兆演出(揺れ)の長さ・強さ |
| `crackGlowController` | `EggCrackGlowController` | 予兆中の発光制御対象(未設定なら`shellWhole`から自動取得) |
| `hatchParticles` / `hatchAudioSource` / `hatchSfx` / `onHatch` | 演出フック | 5章で使い方 |

### `EggCrackGlowController`

| メンバー | 型 | 役割 |
|---|---|---|
| `SetDangerLevel(float amount)` | メソッド | 危険度(0〜1)を亀裂発光・放射光条の両方に反映する。**ゲームロジック側から呼ぶ唯一の入口** |
| `dangerLevel` | `float` | 現在の危険度(Inspectorから直接読み書きも可) |
| `testAutoPlay` | `bool` | **既定true**。本番でタイマー等から制御する場合は必ずfalseにする(1.3節) |
| `radialBurstRenderer` | `Renderer` | 放射光条オブジェクトの参照(未設定なら`Egg_RadialGlow`を自動検出) |

## 4.3 コード例:バランス管理スクリプトから落下破壊をトリガー

「バランスが崩れて落下が確定した」判定を持つスクリプト側の実装イメージです
(落下破壊ガイド4章「B. ロジック駆動」に対応)。

```csharp
using UnityEngine;

public class EggBalanceManager : MonoBehaviour
{
    [SerializeField] private EggBreakController eggBreakController;

    // 揺らし判定などの結果、バランスが崩れて落下が確定したときに呼ぶ
    private void OnEggFellOffPan()
    {
        // TriggerBreak() は多重発火防止つきなので、複数箇所から呼んでも安全
        eggBreakController.TriggerBreak();
    }
}
```

この方式を使う場合は、`EggBreakController.autoTriggerOnCollision` を **`false`** にしておき、
衝突検知とロジック判定が二重に発火しないようにしてください。

## 4.4 コード例:タイマー管理スクリプトから孵化をトリガー

`GameManager.cs`(検証プロジェクトに実在するテスト用スクリプト)は、`Start()` で直接
`TriggerHatch()` を呼んでいる簡易な例です。本番ではタイマーの終了イベントに差し替えます。

```csharp
using UnityEngine;

public class EggTimerManager : MonoBehaviour
{
    [SerializeField] private EggHatchController eggHatchController;
    [SerializeField] private EggBreakController eggBreakController; // 排他制御用(4.6節)
    [SerializeField] private float timeLimit = 20f;

    private float _elapsed;
    private bool _resolved; // 落下破壊 or 孵化のどちらかが確定したか

    private void Update()
    {
        if (_resolved) return;

        _elapsed += Time.deltaTime;
        float progress = Mathf.Clamp01(_elapsed / timeLimit);

        // 残り時間に応じて危険度の発光を更新(4.5節)
        // ...

        if (_elapsed >= timeLimit)
        {
            _resolved = true;
            eggHatchController.TriggerHatch();
        }
    }
}
```

> ⚠️ 検証プロジェクトの `GameManager.cs` は `eggTest`(卵オブジェクト)の参照をInspectorで割り当てないと
> `NullReferenceException` になります。本番用のタイマースクリプトを作る際は、`EggHatchController` を
> 直接シリアライズフィールドで参照する形にすると安全です(上記コード例の形)。

## 4.5 コード例:タイマーの進捗で危険度発光を連動させる

`EggCrackGlowController.testAutoPlay` を `false` にした上で、タイマーの経過に応じて
`SetDangerLevel()` を呼ぶだけで、「時間切れが近づくほど激しく光る」演出になります。

```csharp
[SerializeField] private EggCrackGlowController eggCrackGlowController;

private void Start()
{
    eggCrackGlowController.testAutoPlay = false; // 必ずOFFにする(1.3節)
}

private void Update()
{
    float progress = Mathf.Clamp01(_elapsed / timeLimit);
    eggCrackGlowController.SetDangerLevel(progress);
}
```

なお `EggHatchController.TriggerHatch()` が呼ばれると、内部の予兆処理(`HatchRoutine()`)が
`testAutoPlay` を自動的に退避してOFFにし、`dangerLevel` を0.45秒かけて1まで引き上げてくれるため、
**孵化トリガーが呼ばれた後は、このUpdate側からの`SetDangerLevel()`呼び出しは重複しても実害はありません**
(孵化側が優先して上書きします)が、`_resolved`フラグでUpdate自体を止めておくのがより安全です。

## 4.6 コード例:落下破壊と孵化の排他制御

孵化ガイド8章の未決事項「タイムアウト前に落下したら孵化トリガーは呼ばない」の実装例です。
`EggBreakController`側にも`onBreak`イベントがあるので、そちらで排他フラグを立てる方法も可能ですが、
判定ロジックを1箇所にまとめたほうが事故が起きにくいため、次のように**判定側スクリプトで一元管理**する
方式を推奨します。

```csharp
using UnityEngine;

public class EggOutcomeManager : MonoBehaviour
{
    [SerializeField] private EggBreakController eggBreakController;
    [SerializeField] private EggHatchController eggHatchController;

    private bool _resolved;

    // バランス崩壊 → 落下確定の通知(EggBalanceManager等から呼ばれる)
    public void NotifyFellOff()
    {
        if (_resolved) return;
        _resolved = true;
        eggBreakController.TriggerBreak();
    }

    // タイマー終了の通知(EggTimerManager等から呼ばれる)
    public void NotifyTimeUp()
    {
        if (_resolved) return;
        _resolved = true;
        eggHatchController.TriggerHatch();
    }
}
```

`TriggerBreak()` / `TriggerHatch()` 自体にも多重発火防止(`_hasBroken` / `_hasHatched`)が入っていますが、
それはそれぞれの内部状態だけを見ているため、「落下破壊が起きたのに0.01秒後にタイマーも切れて孵化も
呼ばれてしまう」ような**演出同士の競合**は防げません。上記のように外側で1つのフラグを共有してください。

# 5. 機能拡張の実例:孵化と同時に画面を揺らす

`EggBreakController.onBreak` / `EggHatchController.onHatch` はどちらも `UnityEvent` 型で、
「殻が砕けた瞬間」に自動で `Invoke()` されます(コード上は5章の処理の最後、パーティクル・SE再生と同じ
タイミング)。**新しい演出を追加したいとき、`EggBreakController.cs` / `EggHatchController.cs` 自体を
改造する必要はありません。** カメラシェイク用のスクリプトを1つ作り、そのメソッドをこのイベントに
登録するだけで済みます。

## 5.1 カメラシェイク用スクリプトの実装例

```csharp
using UnityEngine;
using System.Collections;

public class CameraShake : MonoBehaviour
{
    [SerializeField] private float duration = 0.3f;
    [SerializeField] private float magnitude = 0.15f;

    private Vector3 _originalLocalPosition;

    private void Awake()
    {
        _originalLocalPosition = transform.localPosition;
    }

    // onHatch / onBreak から呼び出す公開メソッド
    public void Shake()
    {
        StopAllCoroutines();
        StartCoroutine(ShakeRoutine());
    }

    private IEnumerator ShakeRoutine()
    {
        float elapsed = 0f;
        while (elapsed < duration)
        {
            elapsed += Time.deltaTime;
            float damper = 1f - Mathf.Clamp01(elapsed / duration); // 時間が経つほど弱まる
            transform.localPosition = _originalLocalPosition
                + (Vector3)(Random.insideUnitCircle * magnitude * damper);
            yield return null;
        }
        transform.localPosition = _originalLocalPosition;
    }
}
```

## 5.2 Inspectorから紐付ける方法(コード改変なし・推奨)

1. メインカメラ(またはカメラの親)に `CameraShake` をアタッチする
2. `Egg_Test` の `EggHatchController` コンポーネントを選択し、`On Hatch` の `+` ボタンでイベントを追加
3. 追加した行に、上記1でアタッチしたオブジェクトをドラッグ&ドロップ
4. 関数選択ドロップダウンで `CameraShake.Shake` を選ぶ

これだけで「孵化した瞬間に画面が揺れる」演出が追加されます。落下破壊にも同様に揺らしたい場合は、
`EggBreakController` の `On Break` に同じ手順で登録してください。**Inspectorだけで完結する**ので、
`EggBreakController.cs` / `EggHatchController.cs` を触る必要は一切ありません。

## 5.3 コードから直接購読したい場合(Inspectorを使わない方式)

複数のオブジェクトを動的に生成する構成などでInspector紐付けが使いにくい場合は、`AddListener` で
コードから登録することもできます。

```csharp
private void Start()
{
    eggHatchController.onHatch.AddListener(cameraShake.Shake);
    // 忘れず対で: eggHatchController.onHatch.RemoveListener(cameraShake.Shake); を OnDestroy 等で
}
```

## 5.4 同じ考え方で追加できる他の演出例

`onBreak` / `onHatch` は「殻が砕けた瞬間」に1回だけ呼ばれる汎用フックなので、カメラシェイク以外にも
次のような演出をInspectorから同じ手順で追加できます。

- `Handheld.Vibrate()` を呼ぶだけの薄いラッパーメソッドを登録し、端末バイブレーションを追加する
- スコア加算・実績解除など、演出ではなくゲームロジック側の処理を登録する
- タイムスケールを一瞬0.1倍にする「ヒットストップ」演出用のコルーチンを登録する

いずれも「`UnityEvent`に登録するpublicメソッドを1つ用意する」だけで、既存の演出スクリプトには
一切手を加えずに拡張できます。

# 6. トラブルシューティング

## 6.1 台にコライダーを付けても貫通する

**根本原因(13章で判明した実際の原因)**: 卵メッシュの子オブジェクトに誤って**Rigidbodyを追加していた**ことが
原因でした。親子関係で複数のRigidbodyが混在すると、それぞれが独立に物理挙動をとろうとして干渉し、
貫通やすり抜けが起きます。**Rigidbodyは階層の最上位(親)にのみ設定してください。**

なお、調査の過程で「非凸(Convexなし)MeshCollider + 非キネマティックRigidbody」の組み合わせでも
貫通が再現すること(6秒でY=-175まで落下)、`Convex`を有効にすると解消することも確認済みです。
卵のような単純な凸形状であっても、`MeshCollider`である以上は**必ず`Convex`を有効にする**必要があります
(PhysXの凸包は最大256面制限があるので、複雑すぎるメッシュの場合は衝突用に別メッシュ
(`Egg_Mesh_Collider`など)を用意する方法も検討してください)。

**まとめると、台を貫通する不具合を疑ったら次の順で確認してください:**

1. 卵(または破片)の子オブジェクトに、意図せずRigidbodyが付いていないか
2. MeshColliderを使っている箇所すべてで`Convex`がONになっているか

## 6.2 表示切替の瞬間に破片がワープして見える

殻(`shellWhole`)と破片群(`fracturedPieces`/`hatchFragments`)のローカル座標が**同一原点・回転なし・
スケール1**になっているか確認してください。`TriggerBreak()`/`TriggerHatch()`は「非表示→表示の切替」と
「速度のコピー」だけを行い、座標変換の計算は一切していないため、原点がズレていると即座にワープします。

## 6.3 FBXの再インポートでオブジェクトが100倍(または1/100)のサイズになる

Blenderのエクスポート設定で `Apply Scalings` が `FBX All` になっているか確認してください(3.1節参照)。
これ以外の設定だと、Unity側でオブジェクトの見た目スケールと実際のメッシュサイズがズレます。

## 6.4 テストプロジェクトの「Spaceキー/Hキーでテスト」が効かない

**現状のスクリプトの `Update()` はコメントアウトされており、`enableTestKey`/`testKey` は実際には
機能しません。** 有効なテスト手段は、Playモード中にGame画面へ表示される `Egg Break Test` /
`Egg Hatch Test` パネルの `TriggerBreak` / `TriggerHatch` ボタン(Editor専用のOnGUIデバッグUI)のみです。
本番でキー入力によるデバッグ発火を有効にしたい場合は、コメントアウトされている `Update()` を
有効化するか、独自のデバッグ入力処理を追加してください。

## 6.5 危険度(発光)がロジック側から制御しても変化して見える/変化しない

`EggCrackGlowController.testAutoPlay` が `true` のままになっていないか確認してください(1.3節)。
ONのままだと`Update()`内で毎フレーム`dangerLevel`が自動で上書きされます。
