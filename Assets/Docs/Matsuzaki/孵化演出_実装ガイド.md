# 孵化(成功)演出 実装ガイド

対象: タマゴインキュベーター(仮) / チームメンバー向け
この演出を「触る」ときに知っておくべきことをまとめたドキュメントです。実装は完了済みで、Unity上で動作確認済みです。

---

## 1. できあがったもの(v4: 落下破壊と同系統の物理演算+弱めた勢い)

制限時間を耐えきると、次の3段階で演出が進みます。

1. **予兆(約0.45秒)**: 卵がその場で小刻みに、だんだん激しく揺れながら、ひび割れの発光(`EggCrackGlowController`)が最大まで強まる
2. **破砕**: 卵の殻が薄い8枚の破片に分かれ、**落下破壊(`EggBreakController`)と同じ物理演算(Rigidbody + MeshCollider)**でふわっと弾ける。中心にはキャラクター(現状はカエル風のプレースホルダー)が育つように現れる
3. **落下・静止**: 破片は**本物の重力**を受けて自然に回転しながら落ち、**台(Groundタグのコライダー)にきちんと乗って静止する**。物理演算そのものなので、台を貫通することも、宙に浮いたまま止まることもない

ここまでに何度か作り直していて、それぞれ次の問題を解決しています。

| version | 問題 | 対応 |
|---|---|---|
| v1(上下2分割) | パーツが不自然に重なる / 見る角度によってキャラクターが隠れる | v2で全方位破砕に変更 |
| v2(立体的な破片) | 破片が石ころのように分厚い | v3で外殻だけの薄いメッシュに変更 |
| v3(キーフレームで飛び散り+落下) | 破片が宙に浮いて見える/回転せず落ちる/台という前提がなく貫通してしまう | **v4で落下破壊と同じ物理演算に置き換え**、台の上で自然に静止するようにした |

- 卵がフィールド上のどの位置・どの向きで止まっていても、その場で正しく再生されます(ランダムな回転・完全に横倒しの姿勢の両方でテスト済み)。
- 破片は物理演算そのものなので、台の形状が変わっても(コライダーさえあれば)自動的に馴染みます。
- 落下破壊演出(`EggBreakController`)とは完全に独立していて、お互いに干渉しません。破片の「形状」は流用していますが、メッシュ・Rigidbody・Colliderはすべて別インスタンスです。

## 2. ファイル構成

| 場所 | 内容 |
|---|---|
| `卵のひび割れ.blend`(Blenderファイル) | `HatchShell_01`〜`08`(既存Egg_Fragと同じ境界の、薄い外殻だけの破片・**アニメーションなしの静止メッシュ**) + `Character`(アニメーションあり)を `Egg_HatchRoot` という空(Empty)にまとめてある |
| `Assets/Models/EggHatch.fbx` | 上記9オブジェクトをエクスポートしたもの。`Character` のみアニメーション付き(`Scene` クリップ、フレーム1〜75、30fps)。破片は静止したメッシュとして入っている(動きはUnity側の物理演算が担当) |
| `Assets/Animations/EggHatch.controller` | Animator Controller。`Hatch` トリガーで `Idle → Hatch`(Characterのアニメーション)を再生する |
| `Assets/Scripts/EggHatchController.cs` | 孵化トリガーを受け取り、予兆→破片の弾け→キャラクターのアニメーション、を制御するスクリプト。`EggBreakController.cs` と対になる設計 |

シーン上では `Egg_Test`(卵の親オブジェクト)の子として `EggHatch` という名前で配置済みです。

```
Egg_Test                      ← Rigidbody / EggCrackGlowController / EggBreakController / EggHatchController
 ├─ Egg_RadialGlow
 ├─ EggFragments               ← 落下破壊用(既存、立体的な破片、物理演算)
 │   └─ Egg_Frag_01〜08
 └─ EggHatch                   ← 孵化用(今回追加、初期状態は非表示)
     ├─ HatchFragments          ← 薄い外殻の破片群、各々にRigidbody+MeshCollider(Convex)が付いている
     │   └─ HatchShell_01〜08
     └─ Character               ← Animatorでキーフレームアニメーション再生
```

**破片(`HatchShell_01`〜`08`)の物理設定**は `Egg_Frag` を参考にしつつ、孵化用に重さと減衰を調整してあります(質量が軽すぎると、わずかな力でも速度が暴発するため):

| 項目 | Egg_Frag(落下破壊) | HatchShell(孵化) |
|---|---|---|
| Mass | 0.015 | **0.06** |
| Linear/Angular Damping | 0.05 | **0.3** |
| Collider | MeshCollider(Convex) | 同じ |
| Collision Detection | Continuous Dynamic | 同じ |

## 3. 使い方(他のスクリプトから呼ぶ)

タイマーやゲームマネージャーなど、「制限時間を耐えきった」判定を持っているスクリプトから、次の1行を呼ぶだけです。

```csharp
eggTest.GetComponent<EggHatchController>().TriggerHatch();
```

呼ばれると内部で自動的に、

1. 卵のRigidbodyを `isKinematic = true` にしてその場に固定
2. **予兆**: 卵を小刻みに揺らしながら、`EggCrackGlowController.dangerLevel` を0→1まで引き上げてひび割れの発光を最大にする(`anticipationDuration` 秒かけて)
3. 割れていない殻(`shellWhole`)を非表示にし、`EggHatch` を表示
4. **破片(`HatchFragments`)を物理的に弾く**: 各破片を卵の中心から見た放射方向へわずかに離してから(閉じた状態でぴったり重なっているため、めり込み解消による暴発を防ぐ)、速度を直接指定して(`AddExplosionForce`ではなく)弾く。あとは通常の物理演算(重力・台との衝突)に任せる
5. `Character` のAnimatorで `Hatch` トリガーを発火し、育つアニメーションを再生

の順に処理されます。`EggBreakController.TriggerBreak()` と同様、一度呼ばれると以後は何もしません(誤って2回呼んでも安全)。

### Inspector で調整できる項目(`Egg_Test` の `Egg Hatch Controller` コンポーネント)

| 項目 | 内容 |
|---|---|
| `Anticipation Duration` / `Shake Angle` / `Shake Frequency` | 予兆(揺れ+発光)の長さ・角度・速さ |
| `Crack Glow Controller` | ひび割れ発光を制御する `EggCrackGlowController`。未設定でも`shellWhole`から自動取得される |
| `Pre Physics Separation` | 物理を有効にする直前に破片を放射方向へどれだけ離すか(既定0.03)。値が小さすぎるとめり込み解消で暴発しやすくなる |
| `Min/Max Pop Speed` | 破片が飛び出す速さの範囲(m/s)。既定0.5〜1.1 |
| `Upward Boost` | 上方向へのおまけの初速(m/s)。既定0.4 |
| `Max Spin Speed` | 弾けた瞬間の回転の速さ上限(rad/s)。既定4 |
| `Hatch Particles` / `Hatch Audio Source` / `Hatch Sfx` | 殻が砕ける瞬間に鳴らす光の粒子・SEを差し込める(未設定でも動作する) |
| `On Hatch` (UnityEvent) | カメラ演出・リザルト画面表示など、追加の処理をInspectorから登録できる(殻が砕けた瞬間に発火) |

**もっと勢いを弱めたい/強めたい場合**は、`Min/Max Pop Speed` と `Upward Boost` をまず調整してください。台の素材(摩擦・反発係数)によって着地の跳ね方が変わるので、Physic Materialの調整もあわせて検討すると良いです。

## 4. キャラクターのアニメーション(Blender側)

`Character` はフレーム1〜8で縮んで中心に待機、8〜40で殻が晴れるのに合わせて一気に育ち、55でバウンド、75で着地して静止します。**破片は物理演算なので、Blender側では動かしていません**(静止したメッシュとしてのみエクスポートしています)。

サイズ感の目安: 卵の内寸は概ね 幅1.56 × 奥行1.56 × 高さ2.1(Blender単位)。`Character` は現状、幅0.8×奥行0.73×高さ1.0程度に収めてある。

## 5. キャラクターモデルについて(重要)

**現在入っているキャラクターは仮のプレースホルダー**です(かえるインターンのテーマに合わせた簡易ローポリ形状)。**後日フリー素材などに差し替える前提**とのことなので、差し替え手順は以下の通りです。

1. Blenderで `Character` オブジェクトのメッシュを、正式なモデル(差し替え素材)に置き換える(オブジェクト名は `Character` のまま、`Egg_HatchRoot` の子であることを維持)
2. アニメーション(位置・回転・スケールのキーフレーム)はオブジェクトに紐づいているので、メッシュ形状だけ差し替えれば動きはそのまま引き継がれる
3. 差し替え素材が大きく異なるサイズの場合は、フレーム1(待機時のスケール0.12)と各キーフレームのスケール値を調整してバランスを取ってください
4. **注意**: このテスト環境では卵(`Egg_Test`)がY=3.4付近の高さに置かれていますが、`Character`のアニメーションは卵からの相対座標でしか動かないため、実機で卵が台に接地した状態で孵化する場合は、破片(物理演算で正しく台に落ちる)とキャラクター(卵基準の相対アニメーション)の着地高さがズレないよう、実際の配置に合わせてCharacterのキーフレームのZ位置を微調整してください
5. 差し替え後は下記「6. 再エクスポート手順」に従ってFBXを作り直す

## 6. 再エクスポート手順(Blender → Unity)

Blender側を編集したら、以下の設定で必ず**選択したオブジェクトのみ**をエクスポートしてください。ここでUnity側のスケールが崩れることがあるので要注意です。

1. `HatchShell_01`〜`08` と `Character`、合計9個だけを選択する(`Egg_HatchRoot` 自体は選択しない)
2. `File > Export > FBX` で、`Assets/Models/EggHatch.fbx` に上書き
3. 必ず次のオプションにする(**ここが崩れると被写体が100倍サイズになったりする**):
   - `Apply Scalings`: **FBX All**(`FBX_SCALE_ALL`)
   - `Apply Unit`: ON
   - `Selected Objects Only`: ON
   - `Bake Animation`: ON / `All Actions`: OFF / `Force Start/End Keying`: ON
   - `Forward`: -Y, `Up`: Z(デフォルトのまま)
4. Unity側でファイルを上書きしたら、Projectウィンドウで `EggHatch.fbx` を右クリック→ `Reimport`
5. **破片の数や名前を変えた場合**(オブジェクトの追加・削除など)は、シーンの再構築が必要です。`Egg_Test` の子にある古い `EggHatch` を削除し、`Assets/Models/EggHatch.fbx` を改めてシーンにドラッグ&ドロップして `Egg_Test` の子にし、
   - プレハブ接続を解除(右クリック→ `Prefab > Unpack Completely`。手動でやらないとRigidbody等を追加できません)
   - `HatchFragments` という空オブジェクトを作り、破片をすべてその子にする
   - 各破片に `MeshCollider`(Convex ON)+ `Rigidbody`(Mass 0.06 / Damping 0.3 / isKinematic ON / Use Gravity ON)を追加
   - `Animator` を追加してControllerを割り当て
   - `EggHatchController` の `Hatch Visual` / `Hatch Fragments` / `Character` / `Hatch Animator` / `Crack Glow Controller` 参照を貼り直す

   破片の数・名前を変えていない場合(メッシュ形状だけの差し替えなど)は、既存の `EggHatch` インスタンスがそのままFBXの更新を引き継ぐので、この手順は不要です。

> なぜスケール設定が必要か: このBlenderファイルはシーン単位がメートルのため、`Apply Scalings` が `FBX All` 以外だと、Unityインポート時にオブジェクトの見た目上のスケールと実際のメッシュサイズがズレて、結果的に100倍(または1/100)のサイズになってしまう現象を確認しています。既存の `Egg_Mesh.fbx` と同じ「オブジェクトスケール=1、メッシュサイズがそのまま実寸」という状態に揃えるため、上記設定が必須です。

## 7. 動作確認済みの内容

- 卵をランダムな回転(オイラー角 (20, 10, 5) など)にした状態から `TriggerHatch()` を呼び、予兆(揺れ+発光)→破片の弾け→重力落下→台への着地が正しい順番で再生されることを確認
- 破片の初速が1.3〜2.5m/s程度の穏やかな範囲に収まっており(調整前は質量が軽すぎて12〜25m/sまで暴発するバグがあったが修正済み)、回転しながら自然に台へ落ちて静止することを確認
- ひび割れ発光(`dangerLevel`)が予兆中に0→1へ正しく滑らかに上がることを確認
- 2回目以降の呼び出しでは何も起きない(多重発火防止)ことを確認
- コンソールにエラー・警告が出ないことを確認(※ただし `Assets/Scripts/GameManager.cs` という、`eggTest` 参照未設定のまま `TriggerHatch()` を自動で呼ぶテスト用らしきスクリプトが別に存在しており、そちらは今回のガイドの対象外です。使う場合はInspectorで `eggTest` にEgg_Testを割り当ててください)

## 8. 未決事項(引き続き相談したいこと)

- キャラクターの正式素材への差し替え(手順は上記5節を参照。フリー素材を使う場合はライセンス表記が必要かどうかも確認しておくと安心です)
- 孵化の瞬間の光の演出(パーティクル・SE)は仕組みだけ用意してあるので、素材ができ次第 `Hatch Particles` / `Hatch Sfx` に差し込むだけでOK
- 落下破壊(`EggBreakController`)と孵化(`EggHatchController`)、どちらも未発火の状態で同時に有効になっているため、実際のゲームロジック側で「タイムアウト前に落下したら孵化トリガーは呼ばない」等の排他制御を入れる必要がある(現状は呼び出し側の責任にしてある)
- 実際の台(フライパンなど)のコライダー形状・Physic Material(摩擦・反発)に合わせて、破片の跳ね方や滑り方の調整が必要になる可能性がある
- `ResetForTesting()` は破片群の親(`HatchFragments`)のTransformは初期化するが、個々の破片の位置までは戻さない(Unityの仕様上、Play modeを抜ければ自動的に元に戻るためテストには影響しないが、同じPlayセッション中に2回テストする場合は一度Play modeを抜けてから試すのが確実)
