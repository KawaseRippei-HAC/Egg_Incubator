# EggCrackGlow 実装ガイド

## 1. これは何か

`Custom/EggCrackGlow` は、卵オブジェクトの殻に**内側から光が漏れる亀裂**を表現するURPシェーダーです。
テクスチャ画像は使わず、**シェーダー内で亀裂パターンを計算(プロシージャル生成)**しています。

- 亀裂の模様 = オブジェクト空間の3D Voronoi(セル状)パターンのセル境界線
- 発光の強さ = `_CrackAmount`(0〜1, 危険度)で制御
- `_CrackAmount` が上がると、**既存の亀裂が明るくなる**のではなく、**卵全体に散らばった新しい亀裂が少しずつ増えていく**演出になっている

3Dの位置情報だけで模様を作っているため、UV展開やテクスチャの継ぎ目が一切発生しません。どの角度から見ても同じ密度で亀裂が確認できます。

## 3. 自分のプロジェクトに組み込む手順

1. `Assets/Shaders/EggCrackGlow.shader` を自分のプロジェクトにコピーする
2. 対象の卵メッシュに新しいマテリアルを作成し、Shaderに `Custom/EggCrackGlow` を指定する
3. マテリアルの各パラメータ(下記4章)を、卵のサイズやデザインに合わせて調整する
4. URP Volume Profileに **Bloom** コンポーネントを追加し、Threshold / Intensity を調整する(5章)
5. スクリプトから `material.SetFloat("_CrackAmount", dangerLevel);` を呼ぶだけで危険度に応じた発光になる
   - `EggCrackGlowController.cs` をそのまま使う場合は、対象オブジェクトにアタッチし `dangerLevel` フィールドに0〜1の値を渡すか、外部から `SetDangerLevel(float)` を呼ぶ

### 注意点
- このシェーダーは **オブジェクト空間の座標** を使っているため、メッシュのスケールを極端に変えると亀裂の密度も変わります(`_CrackScale` で調整可能)
- Mesh RendererにはUV座標(_BaseMap用)だけあれば良く、亀裂パターン用のUVは不要です

## 4. 調整可能パラメータ一覧

| プロパティ名 | 役割 | 目安 | 調整すると起きること/|
|---|---|---|---|
| `_BaseMap` / `_BaseColor` | 殻の地の色・テクスチャ | - | 卵の見た目の色そのもの |
| `_CrackScale` | 亀裂の細かさ(Voronoiセル密度) | 1〜20 (既定 7) | 上げるほど亀裂が細かく・多くなる。下げると大きな亀裂が少数になる |
| `_CrackEdgeWidth` | 亀裂1本の太さ | 0.005〜0.3 (既定 0.045) | 上げるほど線が太くなる(発光面積が増える) |
| `_GrowthSoftness` | 亀裂が出現する際のにじみ幅 | 0.01〜0.5 (既定 0.14) | 小さいほどパキッと出現、大きいほどじんわり出現 |
| `_LocalVariation` | 同じ亀裂内でのタイミングのムラ | 0〜1 (既定 0.4) | 1に近いほど線が伸びていく演出が強くなる。0だと1本の亀裂が一瞬で全部光る |
| `_EmissionColor` | 発光色 | 暖色(オレンジ〜黄)推奨 | 卵の中身を連想させる色。冷色系(青など)にすると不穏な印象に変わるので要検討 |
| `_EmissionIntensity` | 発光のHDR強度 | 0〜10 (既定 3.0) | 上げるほどBloomがより強くかかる(Bloom Thresholdとセットで調整) |
| `_CrackAmount` | 危険度(0〜1)。C#から毎フレーム/イベントごとに更新する値 | 0〜1 | 0=無傷、1=亀裂ネットワーク全体が発光。ゲームロジック側の唯一の入力 |
| `_Smoothness` | 殻表面のツヤ | 0〜1 (既定 0.35) | 卵の質感(艶消し〜ツヤあり) |

### 調整の勘どころ
- 「危険度が低いうちからうっすら亀裂が見える」のが気になる場合 → `_GrowthSoftness` を小さくして閾値付近の切り替わりをシャープにする
- 「亀裂が多すぎる/少なすぎる」→ `_CrackScale` を調整(セルの数=亀裂の本数に直結)
- 「Bloomが弱い/強すぎる」→ シェーダー側の `_EmissionIntensity` とVolume Profile側の Bloom Threshold をセットで見る。Thresholdより暗い部分はBloomしないため、両者のバランスが重要

## 5. Bloom設定(Volume Profile)

`Assets/Settings/SampleSceneProfile.asset` に既に以下を設定済みです:

| 項目 | 値 | 意図 |
|---|---|---|
| Threshold | 1.0 | `_EmissionIntensity`(既定3.0)でこの値を超えた部分だけが光る |
| Intensity | 0.6 | にじみの強さ |
| Scatter | 0.65 | 光の広がり方(大きいほど漏れ出す印象が強まる) |
| Tint | 暖色(オレンジ寄り) | 発光色と揃えることで違和感をなくす |
| High Quality Filtering | OFF | モバイル向けの軽量設定 |

別のVolume Profileを使う場合は、Camera側の Universal Additional Camera Data > Render Post Processing がONになっていること、Camera > Allow HDR がONになっていることも確認してください(いずれも本プロジェクトでは設定済み)。

## 6. C#からの使い方(サンプル)

material.SetFloat("_CrackAmount", dangerLevel); // dangerLevel: 0〜1

// EggCrackGlowController.cs を使う場合
eggCrackGlowController.SetDangerLevel(dangerLevel);

EggCrackGlowController.cs には以下のテスト機能が付いています:
- testAutoPlay: ONにすると自動で0→1→0を往復し、見た目を確認できる
- Play中はGame view左上にスライダーが表示され、手動でも危険度を動かせる
- enableHeartbeatSync: ONにすると heartbeatBPM に同期した心拍状の明滅(ドクン・ドッの2山パルス)を発光に重ねられる(将来拡張用)

## 7. 既知の制限・今後の検討事項

- 現状はメインライト1灯を前提にした簡易ライティング(Lambert+簡易スペキュラ)です。追加ライトの影響は受けません(_ADDITIONAL_LIGHTSは将来拡張の余地あり)
- 非常に引き伸ばした綡陓んだメッシュではVoronoiパターンが不均一に見える場合があります(オブジェクト空間座標に依存するため)。極端に非対称なメッシュではX/Y/Zごとにスケール補正が必要になることがあります
- Android実機でのBloomの見え方はPC Editorと差が出ることがあるため、実機確認は必須(受け入れ基準にも記載あり)

## 8. 追加エフェクト:放射光条(EggRadialBurst)

危険度が高まるにつれ、单の外側に不規則な光条(スターバースト状の光漏れ)が放射される演出を追加できます。
亀裂本体とは別オブジェクト・別シェーダーです(理由:亀裂は殻の"表面"の模様、光条は殻の外に漏れ出す"空間的な"光なので、同じメッシュ・同じシェーダーは表現できません)。

### 仕組み
- `Assets/Shaders/EggRadialBurst.shader` を、卵を包む一回り大きな球体(`Egg_RadialGlow`)に適用
- 球面上の方向(角度)から2種類の周波数の光条パターンを計算し、フレネル項で球のシルエット付近だけを光らせる(正面はほぼ透明)ことで、单本体を隠さずに"周囲に漏れ出す光"として見せている
- `_CrackAmount` を亀裂本体と共有しているため、`EggCrackGlowController.SetDangerLevel()` を呼ぶだけで両方が連動する

### セットアップ手順
1. 卵メッシュの子オブジェクトとして球体(卵のバウンディングを覆う程度のスケール)を作成する
2. `Custom/EggRadialBurst` シェーダーのマテリアルを作成・適用する
3. `EggCrackGlowController` の `Radial Burst Renderer` フィールドに、その球体のRendererをアサインする(未設定でも、子オブジェクト名が"Egg_RadialGlow"なら自動検出される)

### 調整可能パラメータ

| プロパティ名 | 役割 | 目安 |
|---|---|---|
| `_RayColor` / `_RayIntensity` | 光条の色・強さ | 発光色と揃えるのが自然 |
| `_RayCountA` / `_RayCountB` | 太い光条・細かい光条の本数 | 既定 9 / 23 (2種類重ねて不規則感を出す) |
| `_RaySharpness` | 光条の鋭さ(高いほど細く鋭い線に) | 既定 14 |
| `_RotationSpeed` | ゆっくり回転させることで生き物らしい揺らぎを出す | 既定 0.15 |
| `_NoiseStrength` | 光条ごとの強弱のランダム性 | 既定 0.6 |
| `_FresnelPower` / `_FresnelFloor` | 卵の正面をどれだけ隠すか(高いほど縁だけに限定) | 既定 3.5 / 0.0 |
| `_MinAmountToShow` | この危険度を超えるまで光条自体を出さない | 既定 0.15 |

## 9. 非線形な"ビビッ"という亀裂進行(改良版)

初期版では危険度の上昇に対して亀裂が滑らかに(線形に)フェードインしていましたが、以下の改良で「不規則に走る」印象に変更しました。

- **ジャギー(`_Jaggedness` / `_JagFrequency`)**: 亀裂が出現する閾値そのものに高周波ノイズで歪みを加え、同じ亀裂の中でも場所によって早く割れる部分・遅れて割れる部分ができるようにした
- **シャープな閾値切り替え(`_GrowthSoftness`を小さく)**: フェードインではなく閾値を超えた瞬間にパキッと出現する
- **スパーク(`_SparkStrength` / `_SparkWidth`)**: 閾値を超えた直後だけ白っぽく一瞬強く閃く演出を追加し、「ビビッ」という走った瞬間の閃光を表現した

これらは全て `Assets/Shaders/EggCrackGlow.shader` 内の `CrackMask()` 関数に実装されています。

## 10. 放射光条エフェクトの改良(集中線スタイル)

初期版は卵を包む球体による「フレネル縁光」でしたが、マンガの集中線(スピードライン)のような
「中心から放射状に伸びる、先端が尖った光条」スタイルに作り直しました。

### 仕組みの変更点
- **オブジェクト形状**: 卵を包む球体(`Egg_RadialGlow`)→ カメラに正対するビルボード板(Quad)に変更
  - `Assets/Scripts/BillboardToCamera.cs` を付与し、常にメインカメラの方を向くようにしている
  - 理由: 集中線は本質的に画面に対して正対する2D的な表現のため、3D空間の球体ではなく常にカメラ正面を向く板の方が絵作りとして自然
- **光条の形状**: UV中心からの角度をセル分割し、セルごとに「角度のズレ・太さ・長さ・出現タイミング」をランダムに割り当てる
  - 半径に応じて角度方向の幅を狭める計算(弧長換算)と、`_TipSharpness` による先端の絞り込みの両方で、根本が太く先端が鋭く尖った針状の光条にしている
- **段階的な出現**: 亀裂本体と同じ考え方で、光条1本1本に個別の出現閾値(危険度)を持たせ、`_RevealSoftness` を小さくすることで「なめらかに伸びる」のではなく「本数がビビッと段階的に増える」動きにしている

### 主な調整パラメータ

| プロパティ名 | 役割 |
|---|---|
| `_RayCount` | 光条の元になる分割数(実際に見える本数は危険度と出現閾値で決まる) |
| `_RayWidth` / `_TipSharpness` | 根本の太さ / 先端の尖り具合 |
| `_RayLengthMin` / `_RayLengthMax` | 光条ごとの長さのばらつき |
| `_CoreRadius` / `_CoreIntensity` | 中心の明るぁ核(発生源)の大きさと強さ |
| `_JitterAngle` | 等間隔にならないようにする角度のランダムなズレ |
| `_RevealSoftness` / `_SparkStrength` | 出現の唐突さ・出現時の閃光(亀裂本体と同じ仕組み) |

## 11. 【重要】コライダーを付けると台を貫通する問題の原因と対処

チームモンバーが卵メッシュにColliderとRigidbodyを付けて平面の台に乗せると貫通する、という不具合を調査しました。

### 結論:モデル自体の問題ではなく、Colliderの設定が原因
卵メッシュの法線・スケール・トポロジーを確認しましたが、法線の反転や非UV由来の不整合は見つかりませんでした
(1472三角形、反転面0、スケール1、UVスフィアベースの綺麗なジオメトリ)。

実際にUnity上で**非凸(Convexなし)MeshCollider + Rigidbody**の組み合わせ��物理シミュレーションを行ったところ、
台を完全に貫通することを確認しました(6秒間のシミュレーションでY=-175まで落下)。
**同じ条件で`Convex`にチェックを入れると、台の上に正しく着地して静止しました。**

**原因**: Unityの物理エンジン(PhysX)は、非凸のMeshColliderを非キネマティックのRigidbodyに付けた場合、
正しい衝突応答を計算できません(すり抜けでしまう)。カプセルコライダーのようなプリミティブ形状は
常に凸形状として扱われるため問題が起きず、複雑な凹凸のあるメッシュ形状のColliderだけがこの制約を受けます。
卵のような単純な凸形状であっても、MeshColliderである以上は明示的に`Convex`を有効にする必要があります。

### 対処法
1. 卵メッシュに`MeshCollider`を追加したら、**必ず`Convex`にチェックを入れる**
2. Convexを有効にすると、PhysXが自動でメッシュから凸包(Convex Hull)を計算する
3. **注意**: PhysXのConvex Hullは最大256面までの制限がある。卵メッシュ(1472三角形、反転面0、スケール1、UVスフィアベースの綺麗なジオメトリ)。比べて確認するとよい
4. **Mesh Collider用に別メッシュを用意する場合**は、Blender側で「衝突用オブジェクト」を別名(例: `Egg_Mesh_Collider`)
   として用意し、同じ階層構造でエクスポートしでエクスポートしておくと、Unity側でも扱いやすい

## 12. 放射光条を「3Dメッシュ」による神秘的な表現に刷新

ビルボード板による集中線は平面的で安っぽく見えるとのフィードバックを受け、
**Blenderで実際に3次元方向へ放射する光条メッシュ(`LightBurst_Mesh`)を作成**し、
透明感のあるグラデーションで発光するシェーダー(`Custom/EggRadialBurst3D`)に刷新しました。

### 作り方
- Blenderで、卵の中心から球面上の完全ランダムな3次元方向へ伸びる細い針状メッシュ(円錐)を90本生成し、
  1つのメッシュとして結合(`Assets/Models/LightBurst_Mesh.fbx`)
- 各スパイクの頂点に**頂点カラーR**で「根本(0)→先端(1)」の距離を記録し、シェーダー側で先端に向かって
  滑らかに透明化するグラデーションを作っている(これが「透明感・神秘的」な質感の核)
- 各スパイクのUV(0).xに、そのスパイクが出現する**危険度の閾値**を個別に記録しており、亀裂本体と同じ
  「本数が段階的にビビッと増える」非線形な出現を、3D空間でも実現している
- シェーダーはフレネル項も加味しており、視線に対して斜めの角度ほど強く発光して覉える
  (ガラスや水蒸気のような透明な質感の演出)

### なぜメッシュにしたか
2Dのビルボード板は、画面に対して常に正対する1枚の絵でしかないため、奥行きのある立体感が出ず
安っぽく見えてしまう。実際の3Dジオメトリとして光条を配置することで、視点を変えたときにも
奥行きのある光条として自然に見える(前面・背面の光条が重なって透けて見える、なども含め)。

### 主な調整パラメータ(`Egg_RadialBurst3D`マテリアル)

| プロパティ名 | 役割 |
|---|---|
| `_RayColor` | 発光色。神秘的な印象にするなら青白〜白系がおすすめ(暖色の卵の発光色とは意図的に対比させている) |
| `_RayIntensity` / `_RootBoost` | 全体の発光強度 / 根本(卵に近い側)の明るさの底上げ |
| `_FalloffPower` | 先端に向かう透明化の滑らかさ(大きいほど先端が早く透明になる) |
| `_FresnelPower` / `_FresnelMin` | 視線角度による透明感の強弱(ガラス質感の調整) |
| `_RevealSoftness` / `_SparkStrength` | 亀裂本体と同じ、段階的な出現の仕組み |

### 再生成・調整したい場合
Blender側の生成スクリプトは `N_SPIKES`(本数)、`length`/`base_radius`の乱数範囲、`sides`(断面の角数)
を変更するだけで覉た目の密度や太さを再調整できる。再エクスポート後はUnity側で
`Assets/Models/LightBurst_Mesh.fbx`を再インポートし、`Egg_RadialGlow`オブジェクトのメッシュを
差し替えれば反映される。

## 13. 【追記】コライダー貫通問題の本当の原因(チーム側で判明)

前回、非凸MeshColliderが原因の可能性を検証しましたが、チームメンバーへの確認の結果、
**実際の原因は「卵メッシュの子オブジェクトにもRigidbodyを設定してしまっていたこと」**でした。

Unityの物理演算は、親子関係にある複数のRigidbodyが混在すると、それぞれが独立した物理挙動を
とろうとして干渉し、意図しない貫通やすり抜けが起きることがあります。
**Rigidbodyは階層の最上位(親)にのみ設定し、子オブジェクト(見た目のパーツや今回の発光エフェクト用
オブジェクトなど)には付与しない**のが正しい構成です。

本プロジェクトの `Egg_Test` 階層でも、`Egg_RadialGlow`(発光エフェクト用の子オブジェクト)などに
誤ってRigidbodyを付けないよう注意してください(確認の結果、現状は子オブジェクトにRigidbodyは
付与されていません)。Colliderについては、11章で検証した「MeshColliderのConvex設定」も
実際に必要な対策なので、あわせて確認することをおすすめします。
