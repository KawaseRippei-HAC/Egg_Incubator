## 2. 現在のヒエラルキー構造

```
Egg_Test (Rigidbody, SphereCollider, MeshFilter, MeshRenderer,
          EggCrackGlowController, EggBreakController)
 ├─ Egg_RadialGlow
 └─ EggFragments (非アクティブ = 待機中)
     ├─ Egg_Frag_01 (MeshCollider Convex, Rigidbody Kinematic)
     ├─ Egg_Frag_02
     ├─ ...
     └─ Egg_Frag_08
```

`EggFragments` は `Egg_Test` と同一のローカル原点(0,0,0)・回転・スケールで子として配置されているため、
表示切替の瞬間にワープ(座標のズレ)は起きません。

---

## 3. 実際のゲームへの取り込み方

このUnityプロジェクトの `Egg_Test` は検証用のオブジェクトです。本番の卵GameObject/Prefabに組み込む場合は次の手順で移植してください。

1. `EggBreakController.cs` はそのまま使い回せます(コピー不要、そのまま参照する)。
2. 本番の卵に **Rigidbody** が必要です。バランス崩壊などの既存の物理演算で使っているRigidbodyがあれば、それをそのまま利用してください(今回追加した物は検証用の簡易設定です)。
3. `EggFragments`(またはそれを複製したもの)を本番の卵の子として配置します。**必ず卵と同じローカル原点(0,0,0)・回転なし・スケール1** に置いてください。ここがズレるとワープして見えます。
4. `EggBreakController` の Inspector で以下を設定します。
   - `Shell Whole` → 割れていない卵メッシュ本体
   - `Fractured Pieces` → 上記の `EggFragments`
5. 破壊トリガーの方式を選びます(次章)。

---

## 4. 破壊トリガーの発火方法(2択)

`EggBreakController` は2つの発火方式を用意しています。Inspectorの `Auto Trigger On Collision` で切り替えます。

### A. 衝突ベース(デフォルト・簡易テスト向け)
`autoTriggerOnCollision = true`、`groundTag = "Ground"`。
台(フライパン)や地面のオブジェクトに `Ground` タグを付ければ、それらに衝突した瞬間に自動で `TriggerBreak()` が呼ばれます。
※ 現在の検証シーンには地面オブジェクトが無いため、このままでは自動発火しません(後述のテスト方法を参照)。

### B. ロジック駆動(本番向け推奨)
`autoTriggerOnCollision = false` にし、「バランスが崩れて落下が確定した」という自分たちのゲームロジック側から

```csharp
eggBreakController.TriggerBreak();
```

を直接呼び出します。バランス崩壊 → 落下 → 着地で割れる、という一連の流れを自前のロジックで正確に制御したい場合はこちらを推奨します。

## 5. 調整可能なパラメータ一覧(Inspector)

| パラメータ | 説明 | 初期値 |
|---|---|---|
| `Base Explosion Force` | 落下速度が0でも最低限加わる爆発力 | 1.5 |
| `Velocity Force Multiplier` | 落下速度(m/s)に比例して爆発力を上乗せする倍率。**「落下の勢いで弾け方が変わる」を実現するパラメータ** | 0.8 |
| `Max Explosion Force` | 爆発力の上限(暴れ防止のセーフティ) | 12 |
| `Explosion Radius` | `AddExplosionForce` の有効半径 | 1.2 |
| `Explosion Upwards Modifier` | 爆発力のうち上方向へ振り分ける割合 | 0.3 |
| `Max Fragment Speed` | 破片の最終的な最大速度(m/s)。飛びすぎ防止 | 8 |
| `Max Fragment Angular Speed` | 破片の最終的な最大角速度(rad/s) | 25 |
| `Ground Tag` | 衝突トリガー方式で使うタグ | "Ground" |
| `Break Particles` / `Break Audio Source` + `Break Sfx` / `On Break`(UnityEvent) | 演出フック。**現在は全て未設定 = 何も再生されません**。担当の方がパーティクル・SE・カメラシェイク処理をここに登録してください | 未設定 |

**チューニングの目安**: `Velocity Force Multiplier` を上げるほど「速く落ちたときだけ激しく割れる」演出になります。まずは既定値のままPlayし、着地速度に対して弾け方が弱い/強いと感じたらこの値を上下させるのが手早い調整方法です。

## 6. 受け入れ基準との対応

仕様書に記載の受け入れ基準と、実装上の対応箇所です。

- [x] **座標のズレ(ワープ)が発生しない** → `shellWhole`/`fracturedPieces` を同一原点に配置し、`TriggerBreak()` 内で同一フレーム中に `SetActive` を切り替えているため発生しません。
- [x] **破片が卵の速度・勢いを引き継ぐ** → `TriggerBreak()` の冒頭で `Rigidbody.linearVelocity`/`angularVelocity` を退避し、各破片へコピーしています。
- [x] **落下の勢いの強弱で弾け方に差が出る** → `explosionForce = baseExplosionForce + impactSpeed * velocityForceMultiplier` で速度に比例させています。
- [ ] **切り替えの瞬間の違和感軽減** → フック(`breakParticles`/`breakAudioSource`/`onBreak`)は用意済みですが、**演出アセット自体は未設定**です。担当の方の登録待ちです。
- [x] **飛びすぎ・めり込み防止の上限** → `maxFragmentSpeed`/`maxFragmentAngularSpeed` で最終速度をクランプしています。

## 7. テスト方法

現在の検証シーンには地面オブジェクトが無いため、衝突ベースの自動発火はまだ試せません。次のどちらかで単体テストできます。

1. **Playモード中に `Space` キーを押す**(`EggBreakController` の `Enable Test Key` が有効な間、`Egg_Test` がどんな状態でも即座に `TriggerBreak()` が呼ばれます)。
2. **PlayモードでGame画面左上の `Egg Break Test` パネルの `TriggerBreak` ボタンを押す**(Editor専用のデバッグUI)。同じパネルの `Reset` ボタンで初期状態に戻せます。

衝突ベースの自動発火を試したい場合は、シーンに床のGameObjectを追加し、タグを `Ground`(なければ Project Settings > Tags and Layers で作成)に設定してください。

## 補足: なぜ「同じ原点を共有する子オブジェクト」構成にしたか

仕様書の技術方針どおり、破片群(`EggFragments`)は卵本体と完全に同じローカル座標系の子として常時待機させています。
これにより `TriggerBreak()` は「非表示→表示の切替」と「速度のコピー」だけで済み、**座標変換の計算ミスによるワープのリスクをゼロ**にしています。
一方で、各破片メッシュ**個別の**ピボット(回転中心)は破片ごとの重心に設定しているため、`AddExplosionForce` や重力による回転が不自然にならないようになっています(コンテナは共有原点、中身の破片は個別ピボット、という二段構成です)。
